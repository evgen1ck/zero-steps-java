# Конкурс грантов

Учебная модель сервера по приложенному заданию. Код использует обычные классы,
интерфейсы, списки, Map, циклы и проверки if. Без Spring, Lombok, Stream API,
HTTP и настоящей базы данных. Данные хранятся в памяти и пропадают при завершении программы.

## Как открыть и запустить

1. Распакуйте архив.
2. В IntelliJ IDEA откройте файл `pom.xml` как проект Maven.
3. Выберите JDK 8 или новее и дождитесь загрузки зависимостей.
4. Запустите класс `TestServer` в `src/test/java`.

Из терминала в папке с `pom.xml`:

```sh
mvn test
```

При первой сборке нужен интернет для загрузки Gson, JUnit и плагинов Maven.
Метода `main` нет: по материалам преподавателя клиентскую часть заменяют тесты,
которые напрямую вызывают методы `Server`.

Проверка подготовленного проекта: исходники скомпилированы с `--release 8`,
18 тестов выполнены через JUnit Platform Console, все прошли. Сам Maven в среде
подготовки не установлен, поэтому команда `mvn test` здесь не выполнялась.

## С чего начать разбор

1. `server/Server.java`: список операций, делегирование сервисам.
2. `service/UserService.java`: регистрация и работа с токенами.
3. `service/ApplicationService.java`: заявки, поиск, оценки.
4. `service/CompetitionService.java`: средняя оценка, сортировка, распределение денег.
5. `database/Database.java`: коллекции с данными.
6. `TestServer.java`: примеры вызовов и проверки результата.

Основной пакет: `academy.tochkavhoda.competition`.

| Подпакет | Что содержит |
| --- | --- |
| `server` | Класс `Server`, методы которого вызывает клиент |
| `service` | Проверки входных данных и выполнение правил конкурса |
| `dto/request` | Объекты для чтения JSON-запросов |
| `dto/response` | Объекты для формирования JSON-ответов |
| `model` | Пользователи, заявки, оценки, результаты |
| `dao` | Интерфейсы доступа к данным |
| `daoimpl` | Реализации интерфейсов, вызывающие `Database` |
| `database` | Единственный экземпляр базы в памяти, Singleton |
| `exception` | Исключение для понятных ошибок пользователя |

Путь запроса: тест → Server → Service → DAO → Database.
Сервисы преобразуют запросы в модели, а модели в DTO-ответы. DTO не зависят от
моделей. Пароли не попадают в ответы. Модели имеют только поля, конструкторы и
геттеры. Для DTO есть также сеттеры. Большая часть файлов — простые классы данных.

## Создание сервера

```java
Server server = new Server(
        1000000L,                              // фонд, целые рубли
        3.0,                                  // порог, оценка должна быть строго выше
        Instant.parse("2030-06-01T12:00:00Z")   // момент X в UTC
);
```

Дата приведена для примера: замените её на срок своего конкурса.
Фонд должен быть неотрицательным, порог — от 0 до 5 включительно.
Некорректная конфигурация вызывает `IllegalArgumentException` при создании сервера.

В программе создаётся один сервер для одного конкурса. База — Singleton.
Повторное создание сервера без очистки базы вызывает `IllegalStateException`.
`Database.getInstance().clear()` нужен только для независимого запуска тестов,
это не операция пользовательского API.

Второй конструктор принимает `Clock`: он нужен тестам, чтобы передвигать время
к моменту X без ожидания и `Thread.sleep`. В обычном коде достаточно конструктора выше.

## Пример использования

Импорты:

```java
import academy.tochkavhoda.competition.server.Server;
import academy.tochkavhoda.competition.dto.response.ServerResponse;
import academy.tochkavhoda.competition.dto.response.TokenResponse;
import com.google.gson.Gson;
import java.time.Instant;
```

После создания сервера:

```java
ServerResponse response = server.registerParticipant(
        "{\"firstName\":\"Иван\",\"lastName\":\"Петров\","
        + "\"company\":\"Старт\",\"login\":\"start\",\"password\":\"pass123\"}"
);
System.out.println(response.getResponseCode()); // 200
System.out.println(response.getResponseData()); // {}

response = server.login("{\"login\":\"start\",\"password\":\"pass123\"}");
TokenResponse loginResponse = new Gson().fromJson(
        response.getResponseData(), TokenResponse.class);
String token = loginResponse.getToken();

response = server.addApplication(token,
        "{\"title\":\"Учебный проект\",\"description\":\"Описание проекта\","
        + "\"directions\":[\"математика\"],\"amount\":50000}"
);
System.out.println(response.getResponseData()); // {"applicationIds":[1]}
```

В этом примере ожидается успешная регистрация. В клиентском коде перед чтением
успешного DTO нужно проверять `response.getResponseCode() == 200`.

## Методы Server

`json` в таблице — строка с JSON-объектом, `token` — строка из ответа `login`.
Методы возвращают `ServerResponse`: код 200 и JSON результата либо код 400
и JSON с единственным полем `error`. Операции без данных возвращают `{}`.

| Метод | Кто вызывает | Что передать / что вернётся |
| --- | --- | --- |
| `registerParticipant(json)` | Без токена | firstName, lastName, company, login, password; ответ `{}` |
| `registerExpert(json)` | Без токена | firstName, lastName, directions, login, password; ответ `{}` |
| `login(json)` | Без токена | login, password; ответ `{"token":"..."}` |
| `logout(token)` | Любой пользователь | Завершает сеанс, сохраняет аккаунт |
| `deleteAccount(token)` | Любой пользователь | Удаляет аккаунт и связанные заявки либо оценки |
| `addApplication(token, json)` | Участник | title, description, directions, amount; ответ со списком applicationIds |
| `addApplications(token, json)` | Участник | applications — массив объектов заявки; ответ со списком applicationIds |
| `cancelApplication(token, json)` | Участник | applicationId; можно отменить только свою заявку |
| `getMyApplications(token)` | Участник | Ответ `{"applications":[...]}` |
| `getApplications(token, json)` | Эксперт | directions — направления поиска; ответ `{"applications":[...]}` |
| `getRatedApplications(token)` | Эксперт | Заявки, которым этот эксперт поставил оценку |
| `rateApplication(token, json)` | Эксперт | applicationId, value; добавляет или заменяет оценку |
| `deleteRating(token, json)` | Эксперт | applicationId; удаляет только свою оценку |
| `getResults(token)` | Любой пользователь | Итоги после момента X; до X — ошибка |

Пример регистрации эксперта:

```json
{"firstName":"Анна","lastName":"Смирнова","directions":["математика","информатика"],"login":"anna","password":"pass123"}
```

Пример нескольких заявок:

```json
{
  "applications": [
    {"title":"Проект 1","description":"Первое описание","directions":["математика"],"amount":10000},
    {"title":"Проект 2","description":"Второе описание","directions":["информатика"],"amount":20000}
  ]
}
```

Если хотя бы одна заявка в списке неверная, не добавляется ни одна.

Пример оценки: `{"applicationId":1,"value":5}`.
Пример поиска: `{"directions":["математика"]}`.
Пример ошибки: `{"error":"Недействительный токен"}`.

Пример итогов:

```json
{
  "ranking": [
    {"applicationId":1,"average":4.5,"amount":50000,"funded":true},
    {"applicationId":2,"average":3.0,"amount":10000,"funded":false}
  ],
  "remainingFund":950000
}
```

`ranking` содержит все заявки в порядке рейтинга. Получатели гранта имеют
`funded: true`. `remainingFund` — нераспределённый остаток.

## Проверки входных данных

- Фамилия, имя, название фирмы, название и описание заявки не могут быть пустыми.
- Логин содержит 3–30 латинских букв, цифр или подчёркиваний; регистр учитывается.
- Пароль содержит минимум 6 символов и не имеет пробелов по краям.
- Списки направлений непустые. Направления приводятся к нижнему регистру,
  пробелы по краям и дубли удаляются.
- Сумма — положительное целое число типа `long`, в рублях.
- Оценка — целое число от 1 до 5. Идентификатор заявки — положительное целое число.
- Отсутствующие обязательные поля и некорректный JSON возвращают ошибку 400.

## Принятые решения для неоднозначных мест задания

Эти решения не выдаются за дополнительные требования преподавателя;
при необходимости их следует согласовать.

1. Одну фирму определяем по её названию без учёта регистра и пробелов по краям.
   Эксперта — по сочетанию имени и фамилии с такими же правилами. Это учебное
   упрощение: однофамильцев с одинаковым именем оно не различает.
   Логины уникальны среди обеих ролей. После удаления аккаунта регистрация заново разрешена.
2. Регистрация не выполняет автоматический вход. Повторный `login` выдаёт новый
   UUID-токен и делает предыдущий токен пользователя недействительным.
3. Для оценки достаточно совпадения хотя бы одного направления заявки со
   специализацией эксперта. Поиск также работает по совпадению хотя бы одного
   запрошенного направления. Все направления поиска должны принадлежать эксперту.
4. Заявка без оценок получает среднюю оценку 0 и не получает грант.
5. Используется средняя оценка, как в подробном алгоритме ТЗ, а не число голосов
   из вводного описания. Оценки перед сортировкой не округляются.
6. При равных средних оценках раньше идёт меньшая сумма. При равенстве обоих
   значений порядок случайный: сначала `Collections.shuffle`, затем стабильная
   сортировка. Результат сохраняется один раз, при повторном запросе порядок тот же.
7. Слишком дорогая заявка пропускается. Следующие заявки всё равно рассматриваются.
   Оценка, равная порогу, уже не даёт грант. Оставшиеся деньги сохраняются.
8. В момент X и после него добавление и отмена заявок, выставление, изменение и
   удаление отдельных оценок запрещены. Регистрация, вход, выход и чтение доступны.
9. В учебной модели нет фонового таймера. Итоги фиксируются при первом запросе
   результатов либо попытке изменить конкурсные данные после X. Перед удалением
   аккаунта также проверяется срок. Поэтому удаление после X не меняет уже
   определившийся результат. Для операции срок проверяется в начале её обработки.
10. Удаление аккаунта разрешено и после X: текущие заявки участника или оценки
    эксперта удаляются, но исторические итоги остаются. В них хранятся только
    номер заявки, средняя оценка, сумма и признак получения гранта — без имени,
    названия фирмы и текста заявки. Это решение согласует удаление аккаунтов
    с неизменностью итогов. После удаления текущие списки и исторический рейтинг
    могут различаться.

Решение рассчитано на последовательные вызовы из тестов, а не на многопоточную
работу настоящего веб-сервера. Пароли в учебной базе хранятся строками, как в
примерах материала; защиту паролей промышленного сервиса здесь не реализуем.

## Что проверяют тесты

Регистрацию и дубли, JSON и обязательные поля, вход и замену токена, роли,
добавление нескольких заявок без частичного сохранения, отмену чужой заявки,
изменение и удаление оценки, среднее, поиск, удаление связанных данных,
ранжирование, недостаток бюджета, порог, отсутствие оценок, устойчивость итогов,
точную границу срока и удаление аккаунтов после неё.
